# 账号模式与设备模式 (v0.7.1)

本文说明局域网安全通讯如何在**不使用服务器密码**的前提下，把身份绑定到中转服务器、在新设备上恢复同一指纹，以及如何用二维码完成添加联系人、连接服务器、配对新设备。

## 1. 两种模式

| | 设备模式（默认） | 账号模式 |
|---|---|---|
| 身份 | 只存在本机（`identity.json` + 密钥） | 本机持有密钥；密文备份存在中转上 |
| 中转 | 可选，仅作传输后备 | 需要一台中转：存放加密身份/历史备份，并按「消息是否留在服务器」转发密文 |
| 重装/换机 | 指纹会变，除非本机还有备份文件 | 用恢复密钥或已有设备上的配对二维码取回同一指纹与历史 |
| 局域网 | 照常发现、直连、端到端加密 | 相同 |

首次运行必须二选一；之后可在设置里切换：

* 设备 → 账号：生成恢复密钥、连接中转、上传加密备份。
* 账号 → 设备：停止向服务器同步；本机身份保留。服务器上的密文备份不会自动删除（可再切回账号）。

逐条消息的「留在服务器 / 仅两端」选择（`default_retain` / 发送时的 `retain`）在两种模式下都有效，影响对离线对端的密文暂存。账号模式额外保证：会话历史和已发送/已接收的文件会以客户端加密的 `LSMBAK02` 备份 blob 存在中转上；新设备用恢复密钥或配对二维码拉取并解密后即可看到这些会话和文件。服务器看不到明文或密钥。设备模式不把身份或历史备份放到服务器。

## 2. 密码学（服务器看不到明文或密钥）

客户端在首次进入账号模式时生成：

* **身份密钥 IK**：现有 Noise X25519 静态密钥，指纹 = SHA-256(IK 公钥)。与今天局域网身份相同。
* **恢复密钥 RK**：16 字节 CSPRNG，显示为  
  `RK1-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX`（32 个大写十六进制字符，每 4 位一组）。
* **查找名 lookup** = hex(SHA-256(`lsm-acct-lookup-v1` ‖ RK 规范化字符串)[0..16])  
  这是服务器上的账户目录名，不是密钥。没有 RK 无法从 lookup 反推 RK。
* **保险库密钥**：备份文件沿用已有 `LSMBAK02` 格式：`Argon2id(RK, salt) → ChaCha20-Poly1305`。内容为身份、联系人、设置、历史密钥、群组密钥、密封的会话历史（`messages.enc` / `history.dat`）以及本地文件附件（单文件上限 4 MiB）。服务器只存这整段密文 blob，看不到明文消息或文件。

消息与文件本身仍然是 Noise 端到端密文。新设备拿不到旧会话的前向保密临时密钥，所以**跨设备历史**来自客户端用 RK 加密后再上传的备份（以及 `server_retain` 的密文 blob），而不是重放 Noise 传输帧。服务器在任何阶段都看不到 RK、IK 私钥或明文。

本机把 RK 密封在 `recovery.dat`（与 `relay.dat` 一样，用历史密钥 ChaCha20-Poly1305），设置页可再次显示以便抄写或出示配对码。IPC 快照里只有 `account_mode`、`account_user`（= lookup）和 `has_recovery_key`，不回传 RK。

## 3. 新设备如何证明「这是我的账号」

没有服务器密码，也不要求用户在中转上另设口令。所有权证明只有两条，任选其一：

### 3.1 恢复密钥

用户在首次开启账号模式时抄下 RK。新设备或重装后：连接同一中转 → 输入 RK → 客户端计算 lookup → `ACCOUNT_GET_BACKUP` 下载密文 → 用 RK 解密 → 写入本机身份（指纹不变）以及历史和文件 → 启动后即可看到先前的会话和附件并继续收发。

任何人只要知道 lookup 都可以下载密文（与旧版备份接口相同）；没有 128 bit RK 无法解密。

### 3.2 已有设备上的一次性配对二维码

1. 已登录的设备生成 32 字节 `token` 和 32 字节包装密钥 `EW`，用 `EW` 密封 RK（`LSMPAIR1` + ChaCha20-Poly1305），经 `PAIR_PUT` 存到中转，TTL 10 分钟。
2. 二维码内容：`lsm://pair?r=host:port&t=<token hex>&k=<EW hex>`。
3. 新设备扫描后：按 `r` 连接该中转（开放中转，无口令）→ `PAIR_GET(token)` → 用 `k` 解开 RK → 与 3.1 相同的备份恢复。
4. 令牌过期或使用后由服务器删除。QR 里的 `EW` 是一次性的，不会长期暴露 RK。

已有设备也可以再次显示长期恢复密钥（用户确认后），效果等同 3.1。

## 4. 中转协议（向后兼容）

P2P 线协议仍是 `PROTO_VERSION = 5`。新能力用 Hello 尾部的 capability 位：

* `CAP_ACCOUNT = 8`：本端理解账号模式与 `lsm://pair` / `lsm://relay`。不向未声明该位的旧对端发送任何新帧（当前也没有新的 P2P 帧；旧对端只是忽略该 bit）。

中转 HELLO 版本仍为 1。`AUTH_OK` 在原有 38 字节后附加可选 `caps: u32`（小端）：

* `CAP_RELAY_ACCOUNT = 1`：支持无密码账户（`ACCOUNT_*` 在口令长度为 0 时不写 `pass.hash`）。
* `CAP_RELAY_PAIR = 2`：支持 `PAIR_PUT/GET`。

旧客户端只读前 38 字节，多出来的 caps 被忽略。旧服务器不带 trailer（客户端视为 `caps = 0`），此时账号注册/配对会提示「服务器不支持账号模式」，局域网设备模式不受影响。

新增帧（旧服务器按「未知类型忽略」处理）：

| 类型 | 名称 | 方向 | 体 |
|---|---|---|---|
| 0x68 | PAIR_PUT | C→S | token[32] · ttl u32 BE · blob |
| 0x69 | PAIR_GET | C→S | token[32] |
| 0x6A | PAIR_DATA | S→C | blob |
| 0x6B | PAIR_MISS | S→C | token[32] |
| 0x6C | PAIR_OK | S→C | token[32] |

`ACCOUNT_REGISTER` / `ACCOUNT_LOGIN` 体格式不变（`u16 user_len | user | u16 pass_len | pass`）。`pass_len == 0` 表示密钥账户：服务器不保存口令哈希。若目录里仍有旧的 `pass.hash`，登录仍按原口令校验（兼容已部署的密码账户；官方客户端不再创建它们）。

中转入网本身继续可以是开放中转（口令为空）。客户端 UI 不提供中转口令输入（既有约定）。

## 5. 二维码 URI

| URI | 用途 |
|---|---|
| `lsm://add?a=ip:port&fp=…&n=…` | 添加联系人（已有）。个人资料页展示「我的二维码」。 |
| `lsm://relay?h=host&p=port` | 连接中转（无口令）。设置/首次运行可展示或扫描。 |
| `lsm://pair?r=host:port&t=…&k=…` | 账号模式配对新设备，见 §3.2。 |

五个 UI 都在个人资料页展示**自己的**「添加我」二维码（`lsm://add?…`，各端用本机地址和指纹绘制）。Android 用 CameraX + ZXing（不用 ML Kit）现场扫码。桌面扫码以粘贴 `lsm://` 链接为主，并提供「从图片识别」：若文件本身是含有链接的文本则直接读取，否则在系统装有 `zbarimg` 时解码图片；没有识别器时提示改为粘贴。

## 6. 各端行为

五个 UI（WinUI、XP、GTK3、GTK4/libadwaita、Android）提供相同选择与文案：

* 首次运行：设备模式 / 账号模式；账号模式可填或扫描服务器、显示恢复密钥、或「恢复已有账号」。
* 设置：切换模式、再次显示恢复密钥、显示配对二维码、粘贴 URI 或从图片识别。
* 个人资料：我的二维码（添加我）。
* Android 会话列表左滑：直接露出 置顶 / 已读 / 免打扰 / 删除 按钮（不再只弹出菜单）。长按仍打开完整菜单。
